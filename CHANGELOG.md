# Changelog

Notable changes to Career Tree, newest first. The V2 architecture replaced V1
in production on 2026-07-19; the V1 log is kept, collapsed, at the end.

*   **2026-08-10** — The pending-dedup keys added 2026-07-28 did not actually dedup, contrary to that entry's "hardened against queue abuse" framing — before this fix the queue was not flood-proof. `md5(proposed_data::text)` hashes `jsonb`, which normalizes object key order but preserves array order, so an edit's `aliases: ["a","b"]` and `aliases: ["b","a"]` are the same change with two different hashes; `lower(trim(suggested_name))` was a near no-op since Zod already trims before insert, leaving only case-folding, so `"Data Scientist"`, `"Data  Scientist"` (double space), `"Data Scientist."`, and a name with a trailing zero-width character were four distinct keys — a flooder rotating one trailing character bypassed the guard entirely. `20260806_pending_dedup_fixes.sql` adds two `IMMUTABLE` SQL functions, `public.suggestion_dedup_key` and `public.edit_dedup_key`, that lowercase, collapse internal whitespace, strip a trailing terminator, and strip zero-width/BOM characters (U+200B–U+200F, U+FEFF) before comparing, and that sort `edits.proposed_data.aliases` before hashing; both the supersede CTEs and the two unique indexes now key on these functions instead of the raw expressions, and the indexes are dropped and rebuilt against production rather than left to the no-op `create unique index if not exists` (pipeline suite 79 → 81).
*   **2026-08-10** — `20260806_pending_dedup_fixes.sql` now takes its strongest lock up front instead of upgrading mid-transaction. The UPDATEs that supersede duplicates take `ROW EXCLUSIVE` on `suggestions` and `edits`, and `CREATE UNIQUE INDEX` needs `SHARE`; requesting `SHARE` only after the UPDATEs ran left a window where a concurrent `POST /api/suggest` or `POST /api/edit` INSERT could land a fresh duplicate that made the index build fail and roll back the whole migration, and once the upgrade was requested every subsequent INSERT queued behind it with no `lock_timeout` — a single idle-in-transaction session (e.g. a forgotten Supabase dashboard tab) could stall the write path indefinitely until POSTs surfaced as Vercel timeouts. The migration now runs `set local lock_timeout = '5s'` and takes `SHARE ROW EXCLUSIVE` on both tables immediately after `begin`, before any mutation, so it either acquires everything it needs up front or fails fast and rolls back cleanly. `docs/OPERATIONS.md` documents the resulting operational contract, including how to find and terminate a blocking idle transaction (pipeline suite 77 → 79).
*   **2026-08-10** — A follow-up migration, `20260806_pending_dedup_fixes.sql`, rebuilds the two pending-dedup partial indexes added by `20260728_pending_dedup_indexes.sql`. That migration is already applied to production, so it cannot be edited in place — Postgres will not re-run it, and its own `create unique index if not exists` would silently no-op against the existing names, so the new migration drops both indexes before recreating them. The rebuild also closes a concurrency gap in both supersede UPDATEs: each matched rows through a `ranked` CTE computed from a snapshot taken before the UPDATE ran, and re-checked only `ranked.rn > 1` — never the row's live `status` — so under READ COMMITTED a row the moderation tool approved between the snapshot and the UPDATE could be rejected on top of its own approval, leaving a Supabase row with both `approval_reason` and `rejection_reason` set while the registry already held the minted node. Both UPDATEs now also require `status = 'pending_review'` on the live row. The private moderation tool's write path gets the mirror-image fix in the same spirit: its Supabase PATCH now scopes on `status=eq.pending_review` by default so it cannot overwrite a row this migration (or another operator) has already resolved.
*   **2026-07-28** — `export_frontend.py --check` no longer reports a fresh clone as stale. The check required both exported snapshots to exist, but `graph.json` has been gitignored and local-only since the 2026-07-21 facts split, so it is absent by design in every clone — the gate exited 1 with `stale: missing …/graph.json` even though the committed `graph.core.json` and all 677 `facts/` files matched the registries exactly. It now always requires the committed artifacts and validates `graph.json` only when a local export is present, so a maintainer whose local full snapshot has drifted is still told. This was the first command the README's "Verify everything" table and `docs/OPERATIONS.md`'s release matrix ask a visitor to run, and the latter specifies a clean worktree — the condition that triggered it. The bug sat in `main()`'s argument-to-artifact wiring, which had no test coverage at all; four `main()`-level regression tests now cover the fresh-clone pass, a locally stale `graph.json`, a missing core snapshot, and stale facts (pipeline suite 71 → 75).
*   **2026-07-28** — Hardened the community write path against queue abuse. Two unique partial indexes now guard the moderation queue (`suggestions` on parent + normalized title, `edits` on target + `md5(proposed_data::text)`), each scoped to `status = 'pending_review'` so a contributor may still re-raise a suggestion once the first has been decided — previously nothing stopped the same payload inserting without limit, since the app only compares a suggestion against the published graph and only rejects an exact no-op edit. Both write routes translate Postgres `23505` into a `409` instead of falling through to the `500` path. Migration `20260728_pending_dedup_indexes.sql` supersedes rather than deletes any duplicates already queued, keeping the never-delete invariant. The homepage counters now filter to `status = 'approved'` ("paths added" / "edits merged"): counting every row put a public number under the direct control of anyone able to POST, so a flood would have surfaced on the homepage within one revalidate window. Also `.gitignore` now globs `.env*` (with `!.env.example`) rather than enumerating three names, and covers `.claude/` and `.impeccable/`.
*   **2026-07-28** — Added a web app manifest (`career-tree/app/manifest.ts`, served at `/manifest.webmanifest`; Next auto-injects `<link rel="manifest">`) so PWA / "Add to Home Screen" surfaces have complete icon coverage. It points at unambiguous static icons — a new 192×192 `public/icon-192.png` plus the existing 512×512 `public/logo.png` — rather than `/icon.png`, which collides between `public/icon.png` and the `app/icon.png` metadata route; `theme_color` is the brand green `#173929` sampled from the logo, on a white background. This does not change the Google search-result favicon, which reads the `<link rel="icon">` tags and still depends on the homepage being indexed.
*   **2026-07-28** — Pre-announcement polish pass, no behaviour change to the graph or the APIs. This update log moved out of `README.md` into this file, taking the front page from 39 KB to 20 KB so it leads with architecture rather than an engineering diary. The sitemap now omits nodes with no edges in either direction — 30 unexpanded exam seeds, 681 entries → 651 — so pages with no route in or out are not offered to crawlers as thin content; they stay routable and are re-included the moment expansion links them. The "Verify everything" table's test counts were stale and are corrected (pipeline 43 → 71, frontend 94 → 97, the latter including a new sitemap-filter regression test). Housekeeping: private tracker IDs dropped from five source comments (the explanations stay), the two dangling `career-tree/lib/slugify.ts` references replaced now that `slugify()` in `pipeline/lib.py` is the only implementation, `.gitignore` section headers de-editorialized, and `LICENSE` now reads 2025-2026 and ends with a newline.
*   **2026-07-23** — Search-appearance pass, prompted by no favicon showing in Google results. Serving was already compliant (48px `.ico`, crawlable, `www` → apex 308), so the fixes target signal quality rather than a break: `app/icon.png` was regenerated at 192×192 from the 1024×1024 original in git history (it advertised `sizes="32x32"`, below Google's multiple-of-48 guidance), and a 512×512 `public/logo.png` now backs new `Organization` (with `logo`) and `WebSite` JSON-LD — neither `WebApplication` nor `LearningResource` has a `logo` property, so the site previously published no machine-readable logo at all. Alongside: the homepage gained a self-canonical; `/map` and `/about` gained their own titles/descriptions/canonicals (both were sitemapped while inheriting the homepage's exact title *and* description); all 681 sitemap entries now carry `<lastmod>` from per-node `prov.generated_at` with the graph build stamp as fallback (`V2Graph` exposes `generatedAt`, invalid dates drop the field rather than emit `Invalid Date`); and guide-page `Article` JSON-LD switched to absolute URLs with `mainEntityOfPage`, `image`, and a `publisher` reference to the new Organization node. 96 vitest tests green. Favicon appearance still depends on Google's separate favicon crawler recrawling the homepage — request indexing in Search Console.
*   **2026-07-21** — The 2026-07-20 V2 scaling audit was verified closed and its docs brought up to date: the hub-page payload fixes (slim parent/child summaries + per-parent context overlays, landed 2026-07-20) hold on the current `main` build — `explore/exam/cat.html` 1,026,820 → 96,826 B, homepage ~704 KB → 27 KB, `.next/server/app` 569 MB/15,067 files → 125 MB/4,613 files, zero dataset strings in client chunks, all 94 vitest tests green. *   **2026-07-21** — The explorer gained its own contribution entry point: a dashed placeholder card (`components/v2/SuggestChildCard.tsx`) renders as the final cell of the "Career options after X" grid and, on terminal nodes, below the retained "Career destination" panel — so an endpoint still reads as a finished career rather than a data gap. Activating it opens the existing `SuggestionDialog` already bound to the current node and returns focus to the card on close. The card matches the sibling child cards' geometry and reuses `POST /api/suggest`, its Zod schema, and the Supabase `suggestions` table unchanged, so explorer-submitted rows are indistinguishable from guide-page ones in review tooling. Previously "Suggest a next option" existed only on `/careers/…`, leaving the explorer — the surface people actually browse options on — with no way to contribute.
*   **2026-07-21** — Raw canonical node IDs (`degree:b-sc`) are no longer displayed to readers: the explore card's meta row now shows only the incoming/next-option counts and the guide footer keeps just its provenance line. The re-audit now reports zero definitive failures across 4,157 URLs.
*   **2026-07-21** — Guide-page route maps now render with React Flow v12: the custom SVG canvas in `RouteMap.tsx` was replaced by a shared `RouteMapFlow` component (smoothstep edges, transit styling preserved — black target pill, dashed laterals, mono type) with a static SSR-fitted inline pane (page scroll passes through; v12 computes the fitted viewport server-side so every node link ships in the prerendered HTML, guarded by a new unmocked `renderToString` test) and the fullscreen dialog as the interactive surface (pan/zoom/Controls, jump buttons via `fitView`, focus-follows-pan for keyboard users); node links re-enable `pointer-events` since React Flow disables them on non-draggable nodes; dagre still supplies positions and `RouteMapEdge.points` was dropped from the model.
*   **2026-07-21** — React Flow migrated from the legacy `reactflow` v11 package to `@xyflow/react` v12 (12.11.2): named `ReactFlow` export, new stylesheet path, and `/map`'s node data is now explicitly typed (`Node<MapNodeData, "canonical">`, checked through `onNodeClick` and the MiniMap color callback) since v12 types node `data` as `Record<string, unknown>` by default — also the prerequisite for optionally rendering guide-page route maps with React Flow, since v12 (unlike v11) can server-render flows whose nodes declare static dimensions.
*   **2026-07-20** — Directory and map search are now debounced and capped: `/search` and `/map` filter on a 150 ms debounced copy of the query (inputs stay fully controlled, one O(N) filter pass per typing burst via the new `lib/v2/use-debounced-value.ts`), the directory renders at most 100 result cards with a polite "N more matches not shown — refine your search" notice (the map needs no cap since React Flow's viewport culling already bounds its DOM), and `lib/v2/search.ts` carries a TODO to move filtering server-side at ~10× nodes.
*   **2026-07-20** — Node pages moved from full prerender to ISR: `/explore` and `/careers` now set `dynamicParams = true` with daily revalidation and prerender only the graph root plus the top 200 nodes by in-degree (deterministic root-first/in-degree-desc/id-asc selection shared via `lib/v2/prerender.ts`), long-tail pages render on first request and cache, unknown slugs still 404 — `.next/server/app` drops from 15,085 files / 371 MB to 4,591 files / 123 MB.
*   **2026-07-20** — Frontend data artifacts are now written compact (no indentation: `graph.json` 10.66 MB → 8.84 MB, `graph.core.json` 1.02 MB → 0.77 MB, and all 677 per-node facts files), with the export detecting and rewriting a structurally current but pretty-printed file exactly once; the call/embedding cache loaders now warn on stderr past 100 MB (TODO: indexed store), and `audit_sources.py` gained `--incremental` to re-audit only URLs lacking a previous reachable result while the full audit stays the release default.
*   **2026-07-20** — Entity-resolution shortlisting is vectorized: the `Resolver` now holds all registry embeddings as one (N×1024) float64 NumPy matrix with precomputed norms (numpy added to `pipeline/requirements.txt`) and scores each candidate via a single `matrix @ query` instead of an O(N) pure-Python cosine loop (~11× faster, top-3 neighbors and scores identical to the old loop), appending a row when a node is minted mid-run while `reg_vecs` keeps serving the exact cached vectors so expansion prompt slices stay byte-identical.
*   **2026-07-20** — `Registry` now keeps `_out`/`_in` adjacency indexes (built on load, maintained by `add_edge` and the new `remove_edge`, mirroring the frontend's `V2Graph` copy-returning semantics), turning `incoming()`/`outgoing()` from O(E) scans into dict lookups — an all-nodes `shortest_trail` sweep drops from 6.8 s to 0.07 s — with the one direct edge deletion (a one-off repair script, since removed) routed through `remove_edge` so nothing can desync the index.
*   **2026-07-20** — Expansion prompts no longer embed the full registry: `Registry.registry_block_for` now builds a bounded, deterministic slice per node (its BFS trail, top-100 embedding neighbors from the already-cached ER vectors, and its same-type cohort, capped at 300 lines / ~3k tokens), keeping prompt size flat as the graph grows and letting unchanged prompts replay from the call cache — the ER resolver remains the real dedup gate and still sees everything.
*   **2026-07-20** — Pipeline registry saves are now batched: `expand.py` checkpoints the registry and frontier together every 25 nodes (and always in a `finally` block, so an interrupted run loses at most 24 nodes) and `enrich.py` gained a `save_every=25` cadence with the same `finally` flush, replacing the per-node full rewrite of `nodes.jsonl`/`edges.jsonl` that cost ~3.7 GB of disk I/O per run.
*   **2026-07-20** — Facts moved out of the server module graph: `export_frontend.py` now also emits `graph.core.json` (all nodes minus `facts`, ~1 MB) plus one `data/v2/facts/{type}--{slug}.json` per node, the app's graph singleton loads the core snapshot, and guide/explorer pages re-attach facts to the focused node on demand via `lib/v2/facts.ts` — shrinking the server data chunk every route loads from 8.8 MB to 0.77 MB (with `outputFileTracingIncludes` keeping the facts files deployable).
*   **2026-07-20** — `next build` static-generation workers are now capped at 4 (`experimental.cpus` in `next.config.ts`); each worker holds the full graph dataset, so the cap keeps peak build memory bounded on many-core machines (measured 8.3 GB → 3.5 GB aggregate RSS).
*   **2026-07-20** — Explore pages stopped shipping one full page view per parent: the client now overlays a small per-parent context (`routes`/`selectedParentId`/`backHref`) on a single canonical view, client-bound edges and node summaries dropped unrendered fields (`prov`, `description`, `is_terminal`), taking `/explore/exam/cat` from ~123 KB to ~94 KB.
*   **2026-07-20** — Explore/guide page payloads slimmed: parents and children now cross the server→client boundary as cached `V2NodeSummary` objects instead of full fact-laden nodes, cutting the heaviest prerendered page (`/explore/exam/cat`) from ~1 MB to ~123 KB.
*   **2026-07-20** — The searchable canonical directory moved from the homepage to a dedicated, statically prerendered `/search` page (now in the sitemap); the hero's "Search for a career" button is a plain link there, and the scroll-to-search button component was removed.

Guide pages also regained their explorer context after a route-refactor regression, the guide back button now uses browser history, the unreachable-route test fixture was refreshed, and the lost `BUGS*.md` local-log ignore rule was restored.
